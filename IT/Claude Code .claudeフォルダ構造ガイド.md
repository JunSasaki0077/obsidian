# Claude Code `.claude/` フォルダ構造ガイド

Claude Code が使う `.claude/` フォルダの構造と各ファイルの役割をまとめた記事の要約。

---

## `.claude/` フォルダは2種類ある

| 場所 | 用途 |
|---|---|
| プロジェクト内 `.claude/` | チーム共通ルール。Gitで共有する |
| `~/.claude/`（ホーム） | 個人の好みやセッション履歴などローカル状態 |

---

## CLAUDE.md

最も重要なファイル。セッション開始時に必ず読み込まれ、システムプロンプトに反映される。

**書くべき内容**
- ビルド・テストコマンド
- アーキテクチャ上の重要な決定
- わかりにくい注意点
- 命名・エラー処理の規約

**書かない方がいいもの**
- リンター設定で済むこと
- 長い理論説明

> [!tip] 200行以内に収める
> 長すぎると指示への追従性が下がる。

個人用の上書きは `CLAUDE.local.md`（自動でgitignore対象）で行う。

---

## `rules/` フォルダ

CLAUDE.md が肥大化したときに、関心事ごとに複数の Markdown ファイルへ分割する仕組み。

YAMLフロントマターで対象パスを指定すると、該当ファイルを編集する際にだけルールが読み込まれる「パス限定ルール」も可能。

```yaml
# 例: src/api/**/*.ts を編集するときだけ読み込まれるルール
```

---

## hooks システム

CLAUDE.md の指示は「提案」に過ぎないが、hooks は特定イベントで確実に発火するスクリプト。決定論的な制御を実現する。

設定は `settings.json` の `hooks` キーに記述する。

**終了コードの意味**

| コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | エラーだが処理継続 |
| 2 | 停止してエラー内容をClaudeに渡し自己修正させる |

**代表的なイベント**

| イベント | タイミング | 用途例 |
|---|---|---|
| PreToolUse | ツール実行前 | 危険コマンドの遮断 |
| PostToolUse | ツール実行後 | フォーマッタ適用 |
| Stop | 終了時 | テスト通過の確認 |
| UserPromptSubmit | プロンプト送信時 | - |
| Notification | 通知時 | - |
| SessionStart / SessionEnd | セッション開始・終了時 | - |

**注意点**
- hooks はセッション中に再読み込みされない
- PostToolUse は実行済みの操作を取り消せない
- サブエージェントの操作にも再帰的に発火する
- フルユーザー権限・無サンドボックスで実行される

---

## `skills/` フォルダ

Claude が文脈に応じて自動的に呼び出せる再利用可能なワークフロー。

- 各スキルはサブディレクトリ内の `SKILL.md` で説明される
- 関連ファイルも同梱できる（コマンドは単一ファイル、スキルは「パッケージ」）
- 個人用スキルは `~/.claude/skills/` に置けば全プロジェクトで使える

---

## `agents/` フォルダ

複雑なタスク用に特化したサブエージェントの人格を定義する Markdown ファイル群。

- ツールアクセス権やモデルを個別に指定できる
- 読み取り専用なら Haiku、重要な作業は Sonnet/Opus など使い分け可能
- エージェントは独立したコンテキストで作業し、結果だけをメインセッションに報告 → トークン節約になる

---

## `settings.json`

Claude が実行できる操作を制御する権限設定ファイル。

| キー | 内容 |
|---|---|
| allow | 確認不要で実行できるコマンド（例: `npm run`、`git` 読み取り系） |
| deny | 完全に禁止するコマンド（例: `rm -rf`、`.env` の読み取り） |

どちらにも該当しない操作は都度確認が入る。個人用の上書きは `settings.local.json` で行う。

---

## グローバルの `~/.claude/`

- `CLAUDE.md` → 全プロジェクト共通の個人指示
- `projects/` → セッション履歴と自動メモリが保存される（`/memory` コマンドで閲覧・編集可能）

---

## 始め方のステップ

1. `/init` で `CLAUDE.md` の初期版を生成して整理する
2. `.claude/settings.json` で最低限の allow/deny ルールを設定する
3. よく使うワークフロー用のコマンドを1〜2個作る
4. `CLAUDE.md` が肥大化したら `rules/` へ分割する
5. `~/.claude/CLAUDE.md` に個人の好みを追加する

---

## まとめ

- `CLAUDE.md` が最も効果の高いファイル
- `.claude/` フォルダ全体は「Claude に自分やプロジェクトのことを伝えるプロトコル」
